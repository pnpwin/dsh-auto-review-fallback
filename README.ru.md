# DSH Auto Review Fallback

Отдельная модель проверки команд и безопасная упорядоченная fallback-цепочка для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness).

[English](./README.md) · Русский

> Неофициальный плагин [pnpwin](https://github.com/pnpwin). Auto review экспериментален: ошибочное разрешение модели может запустить небезопасную команду с полным доступом. Более лёгкая модель не обязательно надёжнее оценивает риск.

## Возможности

- Выбор отдельной пары **провайдер + model ID** для Auto review, без изменения модели диалога.
- Основная модель и до **7 резервных**, проверяемых строго по порядку.
- Тайм-аут одной попытки **1–120 секунд**, по умолчанию 20.
- Необязательный reasoning effort для каждой модели. Пустое поле использует значение адаптера по умолчанию.
- Провайдеры и их названия из тех же источников, что **Settings → Models**; модели — из общего каталога DSH, с сохранением явно настроенных и ручных ID.
- Полный выпадающий список вместо фильтрующего `datalist`.
- Интерфейс EN/RU, штатные токены темы и сохранение через DSH settings с контролем revision.
- Встроенное исправление Codex `Unsupported parameter: temperature`, в том числе в режиме модели сеанса.

## Официальный источник

Плагин расширяет [`@deepseek-ai/dsh-experimental-auto-review`](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/experimental/auto-review) через `llm/stream`. Штатные политика безопасности, строгий парсер и gate выполнения инструментов не копируются и не заменяются.

Исходная проблема с Codex описана в [Discussion #12495](https://github.com/deepseek-ai/deepseek-harness/discussions/12495). Точная ревизия и границы реализации — в [описании происхождения](./UPSTREAM.md).

## Требования и установка

Поддерживаемая версия — **DSH 0.2.2-rc.1**, профиль Web/Desktop и включённый штатный экспериментальный Auto review. Локальная реализация проверялась в macOS Desktop; другие версии/платформы и CLI-разрешение модулей не проверены. Для тестов нужен Node.js 24.9.0+.

Это GitHub bundle, не публикация в npm. Зависимостей, install-скриптов и сборки нет.

```sh
git clone https://github.com/pnpwin/dsh-auto-review-fallback.git
cd dsh-auto-review-fallback
dsh plugin --profile desktop add "$PWD"
```

Вместо `desktop` укажите свой профиль. Также можно установить абсолютный путь к папке через Plugin Manager. Затем обновите существующую страницу DSH и откройте **Настройки → Auto review**. Профиль может ссылаться на эту папку: не перемещайте и не удаляйте её до удаления bundle.

После обновления через `git pull` перезапустите DSH и обновите страницу: обычная перезагрузка браузера не заменяет закэшированный Host-код.

**Переход с локального прототипа:** сначала выключите/удалите `@local/dsh-auto-review-router`. Не запускайте одновременно два отдельных маршрутизатора Auto review. У опубликованного пакета свой namespace `pnpwin-auto-review-fallback`; существующие цепочки автоматически не переносятся. Публикация репозитория сама по себе не меняет локальную установку.

## Настройка

По умолчанию выбран режим **«Модель текущего сеанса»**: новые провайдеры не выбираются автоматически. Для отдельной модели:

1. Выберите собственную цепочку.
2. Задайте основного провайдера и модель, добавьте резервные и расставьте порядок.
3. Оставьте effort пустым, если не знаете точное поддерживаемое значение. Ошибка `UNSUPPORTED_REASONING_EFFORT` — ошибка конфигурации, а не причина попробовать другую модель.
4. Задайте тайм-аут и нажмите **«Сохранить»**.

Новые настройки применяются к следующим проверкам. Начатая проверка использует снимок прежней цепочки. Модель диалога и режим доступа сеанса не меняются. После изменений в Models повторно откройте страницу или нажмите «Обновить каталог».

## Безопасность и fallback

Это последовательная цепочка, не случайный pool, не голосование и не поиск более разрешающей модели. Каждая новая проверка снова начинается с основной.

Переход к следующей модели возможен только при распознанной технической недоступности: лимите, quota, тайм-ауте, сетевой/транспортной ошибке, выбранных серверных ошибках или недоступном маршруте/модели/учётных данных.

**Отказ `deny`, некорректный JSON, max-tokens, неподдерживаемый effort, отказ политики и неизвестная ошибка не запускают fallback.** После уже завершённого текстового ответа техническая ошибка тоже не отправляет запрос другой модели.

При общей отмене следующая модель не запускается. Предыдущий транспорт должен подтвердить завершение; при неудачной очистке команда блокируется. Если недоступна вся цепочка, возвращается `AUTO_REVIEW_ROUTES_EXHAUSTED`, тело инструмента не исполняется. Частичные неудачные ответы не смешиваются с резервными. Буфер ограничен 2 MiB и 20 000 chunks.

Каждый выбранный провайдер, до которого дошла цепочка, получает штатный вход проверки: политику, удержанные инструкции/историю и аргументы вызова инструмента. Выбирайте только доверенные организации и endpoint. Плагин не логирует промпт, ответ, учётные данные или причину отказа; в логах могут быть provider/model ID и технический статус. Ошибочное решение модели этим механизмом не исправляется.

## Проверка

```sh
npm test
node --check host.js
node --check client.js
```

Тесты без внешних зависимостей проверяют цепочку, fail-closed исходы, отмену, дренирование, параллельность, снимок настроек, каталог Models, явные remote-зависимости, metadata, переносимое разрешение модулей и Codex compatibility. Реальные LLM-запросы не выполняются.

Локальный прототип дополнительно проверялся через настоящий DSH LlmRuntime и каталог подключённых провайдеров. Пользователь подтвердил работоспособность исходного исправления Codex. Переименованный публичный пакет не устанавливался поверх рабочего локального плагина; сквозная проверка браузерных кликов и сохранения для него не заявляется. Для ручного теста включите Auto review и попросите выполнить только `pwd`, без изменений. Не проверяйте отказы настоящими опасными командами.
